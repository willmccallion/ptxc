# Architecture

ptxc compiles an ONNX model to PTX kernels plus a static execution plan, and
runs it through the CUDA driver API. Nothing on the compiler path calls
cuBLAS, cuDNN, CUTLASS or NVRTC. The design borrows the graph-level ideas from
XLA, separates compute from schedule as Halide and TVM do, and tunes
schedules with Ansor's sketch-and-search method.

Target hardware for development: RTX 4060 Ti (Ada, sm_89, 8 GiB). Nothing in
the IRs names an architecture. The architecture lives in `ptxc-target` as
data.

## Pipeline

```
ONNX bytes
  │ ptxc-onnx        parse protobuf, typed attributes, shape inference via op type rules
  ▼
Graph                (ptxc-graph)
  │ ptxc-graph-opt   rewrites, CSE, DCE, constant folding (via ptxc-interp), layout, QDQ folding
  ▼
Graph
  │ ptxc-graph-opt   fusion partitioning, attention matching
  ▼
Partitioned          (ptxc-graph: every node in exactly one FusedGroup)
  │ ptxc-lower       one ComputeDef per group
  ▼
ComputeDef           (ptxc-loop)
  │ ptxc-schedule    split-K where a product leaves the GPU idle (D75);
  │                  rule → sketch → trace (from the tuning database or defaults)
  ▼
Schedule<Validated>  (ptxc-loop)
  │ ptxc-loop        lowering
  ▼
LoweredKernel        (ptxc-loop; runnable on CPU by the loop interpreter)
  │ ptxc-codegen         instruction selection → PtxModule → text
  ▼
KernelSpec + BufferPlan + Steps
  │ ptxc-compiler    memory planning, emission
  ▼
Program              (ptxc-program; serialisable, IR-free)
  │ ptxc-runtime     load modules, one arena, eager or CUDA graph replay
  ▼
outputs
```

`ptxc-compiler` drives the stages as a typestate, so a stage cannot run out
of order:

```rust
pub struct Compilation<S> { state: S, target: Target, options: Options }

impl Compilation<Imported>    { pub fn optimize(self) -> Result<Compilation<Optimized>, CompileError> }
impl Compilation<Optimized>   { pub fn partition(self) -> Result<Compilation<Partitioned>, CompileError> }
impl Compilation<Partitioned> { pub fn lower(self) -> Result<Compilation<Lowered>, CompileError> }
impl Compilation<Lowered>     { pub fn schedule(self, db: &TuningDb) -> Result<Compilation<Scheduled>, CompileError> }
impl Compilation<Scheduled>   { pub fn emit(self) -> Result<Program, CompileError> }
```

Each state struct holds that stage's output (`Imported { graph: Graph }`,
`Lowered { partitioned: Partitioned, groups: IndexVec<GroupId, LoweredGroup> }`,
and so on).

## Stages

### Frontend (`ptxc-onnx`, `ptxc-onnx-proto`)

- **In:** `&[u8]` holding a `ModelProto`. External data is resolved relative
  to the model's path.
- **Out:** `Graph`, or `ImportError` naming the node, the op and the reason.
- Attributes are parsed once into per-op structs such as `ConvAttrs`. After
  import, nothing reads a string-keyed attribute again.
- Negative axes are normalised to `Axis` here. Default attribute values are
  filled in by opset version, so later stages see one canonical form.
- Shapes come from the op type rules (`TypeRule` in `ptxc-graph`). The
  frontend calls `GraphBuilder`, which infers each node's output types as it
  is added. Declared `value_info` shapes are checked against the inferred
  ones, and a mismatch is an error, not something to trust.
- Unsupported ops, dtypes, opsets below 13 (D28), symbolic dimensions and
  control flow (`If`, `Loop`, `Scan`) are rejected with a typed error. The
  conformance report counts each of these as *unsupported*, separately from
  *failed*.
- The protobuf types are generated by prost from a pinned `onnx.proto` and
  committed to the repository (see DECISIONS.md, D7).

### Graph IR (`ptxc-graph`)

The graph IR is SSA dataflow in typed arenas, in the style of XLA's HLO
module but with ONNX's op set.

```rust
define_index!(NodeId);
define_index!(ValueId);
define_index!(ConstantId);

pub struct Graph {
    nodes: IndexVec<NodeId, NodeSlot>,     // NodeSlot::{Live(Node), Erased}; compact() renumbers
    values: IndexVec<ValueId, Value>,
    constants: IndexVec<ConstantId, HostTensor>,
    uses: IndexVec<ValueId, Vec<Use>>,     // maintained only by GraphBuilder and Rewriter
    inputs: IndexVec<GraphInputIndex, ValueId>,
    outputs: IndexVec<GraphOutputIndex, ValueId>,
}

pub struct Node { op: Op, operands: IndexVec<OperandIndex, ValueId>, outputs: IndexVec<NodeOutputIndex, ValueId> }

pub struct Value { ty: TensorType, def: ValueDef, name: Option<ValueName> }

pub enum ValueDef {
    Input(GraphInputIndex),
    Constant(ConstantId),
    Output { node: NodeId, index: NodeOutputIndex },
}

pub enum Use {                             // graph outputs are uses, so "no uses" means dead
    Operand { node: NodeId, index: OperandIndex },
    GraphOutput(GraphOutputIndex),
}

pub struct TensorType { dtype: DType, shape: Shape, layout: Layout }   // Layout::RowMajor until M4's layout pass

#[derive(Clone, PartialEq, Eq, Hash)]
pub enum Op {                              // canonical forms: D32
    Unary(UnaryOp), Binary(BinaryOp), Variadic(VariadicOp), Where, Cast(CastAttrs),
    Activation(Activation), Clip, PRelu,
    MatMul, Gemm(GemmAttrs),
    Conv(ConvAttrs), Pool(PoolAttrs), GlobalPool(GlobalPoolKind),
    Reduce(ReduceAttrs), ArgReduce(ArgReduceAttrs), CumSum(CumSumAttrs),
    Softmax(SoftmaxAttrs), LayerNorm(LayerNormAttrs), BatchNorm(BatchNormAttrs), InstanceNorm(InstanceNormAttrs),
    Reshape(Shape), Expand(Shape), Transpose(TransposeAttrs), Tile(TileAttrs), Concat(Axis),
    Slice(SliceAttrs), Split(SplitAttrs), Pad(PadAttrs), Trilu(TriluAttrs),
    Gather(Axis), GatherElements(Axis), GatherNd(Rank),
    Quantize(QuantizeAttrs), Dequantize(DequantizeAttrs), QMatMul(QMatMulAttrs), QConv(QConvAttrs), // QMatMul's result: a grid or a float type (D72)
    Resize(ResizeAttrs),
    Attention(AttentionAttrs),             // ONNX's Attention; the M6 matcher produces it too
}

pub trait TypeRule {
    fn infer(&self, inputs: &[&TensorType]) -> Result<Vec<TensorType>, TypeError>;
}
```

Invariants, which `verify.rs` checks after every pass in tests:

- every value has exactly one definition, and every use refers to a live node;
- the graph is acyclic;
- every node's output types equal what its type rule infers from its inputs;
- the use lists match the node inputs.

`Op` is `Eq + Hash`. Float attributes are stored by their bits through a
newtype. This gives CSE structural hashing for free. It is also the property
an e-graph needs, so a future e-graph engine can treat `Op` as its e-node
label without changing `Op`.

Shapes are static in v0.1.0 (D3). `Dim` is a newtype over `u64`. Adding a
symbolic variant later turns it into an enum without changing its users'
signatures.

**Text format.** `text/print.rs` and `text/parse.rs` round-trip graphs. Pass
tests read and write graph IR text, in the style of MLIR's FileCheck tests:

```
graph @mlp(%x: f16[8, 784]) -> (f16[8, 10]) {
  %w1 = const f16[784, 256] #0
  %h  = matmul %x, %w1 : f16[8, 256]
  %r  = relu %h : f16[8, 256]
  ...
}
```

**Fusion result.** Partitioning produces a different type from `Graph`,
because "every node belongs to exactly one group" is an invariant the graph
itself cannot express:

```rust
pub struct Partitioned { graph: Graph, groups: IndexVec<GroupId, FusedGroup>, group_of: IndexVec<NodeId, Option<GroupId>> }
pub struct FusedGroup { nodes: Vec<NodeId> /* topological */, inputs: Vec<ValueId>, outputs: Vec<ValueId>, kind: GroupKind }
pub enum GroupKind { Injective, Reduction, MatMulEpilogue, ConvEpilogue, Attention, View }
```

Groups are numbered so each comes after the groups computing its inputs. A
group's outputs are only the values read outside it. In M2,
`Partitioned::one_node_per_group` is the only partitioner.

`View` groups (reshape, or squeeze on contiguous data) produce no kernel:
they become buffer aliases in the memory plan. Until the memory plan aliases
them, lowering gives a reshape a copy stage like any other op.

### Graph optimisation (`ptxc-graph-opt`)

- **In and out:** `Graph`. Partitioning goes from `Graph` to `Partitioned`.
- `Pass` trait: `fn run(&self, graph: &mut Graph) -> Result<PassReport, PassError>`.
  `PassManager` runs passes in order and runs the verifier after each one
  when `cfg(debug_assertions)` is on or a test asks for it.
- **Rewrite rules are data:**
  `RewriteRule { name, lhs: Pattern, rhs: Template, guard: Guard }`.
  `RewriteEngine` is a trait. `GreedyEngine` (a worklist, as in MLIR's
  greedy pattern driver) is the v0.1.0 implementation. An `EGraphEngine`
  (equality saturation in the style of `egg`, plus cost-based extraction)
  can be added in `rewrite/egraph.rs` and consume the same rule sets. Rules
  are never closures, so no rule needs rewriting to switch engines.
- **Constant folding** runs `ptxc-interp` on subgraphs whose inputs are all
  constant, as XLA folds with its HloEvaluator. Folding therefore cannot
  disagree with the golden model. A size limit stops folding from inflating
  weights, for example by materialising a broadcast.
- **QDQ folding** (`rules/qdq.rs`) turns a `Dequantize → MatMul/Conv →
  Quantize` chain into `QMatMul`/`QConv`, as TensorRT's explicit
  quantization does, and a `Dequantize → MatMul` chain into a `QMatMul`
  with a float result (D72).
- **Layout** chooses NHWC or NCHW per convolution chain and pushes
  transposes to group boundaries. A layout is part of `TensorType`, never an
  implicit convention.
- **Partitioners** implement `Partitioner`. The greedy one fuses injective
  consumers into their producer's epilogue and elementwise ops into
  reductions, following XLA's producer-consumer fusion. The attention matcher
  (M6) runs first and claims whole attention subgraphs.

### Reference interpreter (`ptxc-interp`)

- **In:** `&Graph` and input `HostTensor`s. **Out:** output `HostTensor`s.
  Implements `Evaluate`.
- It is deliberately naive: direct loops written from each op's definition,
  with no blocking and no shared code with `ptxc-lower`. If the golden model
  and the compiler shared code, they could share a bug.
- Numerics (`numeric.rs`):
  - f16, bf16 and FP8 inputs are widened to f32, computed, and rounded to
    the output type with round-to-nearest-even.
  - Matmul, convolution and reduction accumulate in f64 for float types and
    in i64 for integer types, so the reference is at least as accurate as
    anything it judges.
  - Quantize and dequantize follow the ONNX definitions exactly, including
    saturation.

### Loop IR (`ptxc-loop`)

Three layers, as in Halide and TVM.

**1. Compute: what each output element is.**

```rust
define_index!(IterVarId); define_index!(TensorParamId);
pub struct ComputeDef {                               // made only by ComputeBuilder::finish, which type-checks it
    name: ComputeName,
    exprs: ExprArena,                                 // index arithmetic
    vars: IndexVec<VarId, IndexVar>,                  // IndexVar::{Iter(IterVarId), Loaded { tensor, index }}
    iter_vars: IndexVec<IterVarId, IterVar>,          // spatial and reduction axes
    inputs: IndexVec<TensorParamId, TensorParam>,     // name, dtype, shape
    outputs: Vec<OutputDef>,                          // name, dtype, TensorExpr; shape = spatial extents
}
pub struct IterVar { name: VarName, extent: Dim, kind: IterKind }   // IterKind::{Spatial, Reduce}
pub enum TensorExpr {
    Load { tensor: TensorParamId, index: Vec<ExprId>, padding: Option<Scalar> }, // padding read outside (D71)
    Const(Scalar), Index { index: ExprId, dtype: DType },     // an index read as an integer value
    Unary(UnaryOp, Box<TensorExpr>), Binary(BinaryOp, Box<TensorExpr>, Box<TensorExpr>),
    Cast { to: DType, overflow: Overflow, value: Box<TensorExpr> },
    Select { condition: Box<TensorExpr>, then: Box<TensorExpr>, otherwise: Box<TensorExpr> },
    Reduce { op: ReduceOp, axes: Vec<IterVarId>, body: Box<TensorExpr> },          // Sum, Prod, Max, Min
    ArgReduce { kind: ArgKind, tie: TieBreak, axis: IterVarId, body: Box<TensorExpr> },
}
```

The scalar operations are the primitives every v0.1.0 graph op lowers onto:
arithmetic, both remainders, comparisons, logic, `exp`, `log`, `erf`,
`tanh` and the other transcendental functions, rounding, and NaN and
infinity tests. Activations, softmax and normalisation are compositions,
built by `ptxc-lower`. FP8 is storage only here too: it reaches arithmetic
through `Cast`. A gather's index is an `IndexVar::Loaded`, an integer read
from an index tensor, so index arithmetic never reads data directly; the
other direction, an index read as data, is `TensorExpr::Index`, which masks
running sums and triangles. An arg-reduction over an empty axis gives 0.
A definition is one stage: at most one reduction, and then exactly one
output; every load not indexed through a gather stays within its tensor over
the iteration domain (D40), unless it is padded: a window's read of a
convolution's or pool's input gives its padding where it leaves the input,
as Halide's `constant_exterior` does (D71).

**2. Schedule: how to iterate.** A loop tree is transformed by primitives.
Every applied primitive is recorded in a `Trace`, as in TVM's MetaSchedule.
The trace is replayable, serialisable, and is exactly what a tuning record
stores.

```rust
pub struct Schedule<S> { compute: Arc<ComputeDef>, loops: LoopTree, trace: Trace, state: S }
pub struct Open; pub struct Validated { threads: ThreadsPerBlock, tiles: Vec<Vec<Dim>> }

impl Schedule<Open> {
    pub fn new(compute: Arc<ComputeDef>) -> Self;                        // spatial loops outermost, then reductions
    pub fn replay(compute: Arc<ComputeDef>, trace: &Trace) -> Result<Self, ScheduleError>;
    pub fn apply(&mut self, step: Primitive) -> Result<(), ScheduleError>;
    pub fn split(&mut self, loop_: LoopId, factors: Vec<SplitFactor>) -> Result<Vec<LoopId>, ScheduleError>;
    pub fn fuse(&mut self, loops: Vec<LoopId>) -> Result<LoopId, ScheduleError>;
    pub fn validate(self, target: &Target) -> Result<Schedule<Validated>, ScheduleError>;
}
impl Schedule<Validated> { pub fn lower(&self) -> Result<LoweredKernel, LowerError> }

pub enum Primitive {                                    // compute-at and layout
    Split { loop_: LoopId, factors: Vec<SplitFactor> },  // come with M3
    Reorder { order: Vec<LoopId> }, Fuse { loops: Vec<LoopId> },
    Bind { loop_: LoopId, axis: ThreadAxis },          // blockIdx/threadIdx.{x,y,z}; never an empty loop
    Unroll { loop_: LoopId }, Vectorize { loop_: LoopId },
    CacheRead { tensor: TensorParamId, at: LoopId },   // the input's tile in shared memory, filled at `at`
    Tensorize { m: LoopId, n: LoopId, k: LoopId, instruction: MmaInstruction }, // one mma per warp
    Pipeline { loop_: LoopId, stages: StageCount },     // the tiles staged at `loop_` filled `stages - 1` ahead
    Swizzle { tensor: TensorParamId, swizzle: Swizzle }, // the staged tile's bytes XOR-permuted
    Reindex { tensor: TensorParamId, groups: Vec<Vec<IterVarId>> }, // the tile a box in the iteration space (D70)
}
```

The `LoopTree` keeps every axis's index as an expression over the current
loop variables, simplified after each primitive with the loops' ranges (D38),
and the guards a nest needs (D39). A split whose factors do not divide the
extent rounds the outer loop up and adds a guard `index < extent`.

`validate` checks the schedule against the target: thread counts, shared
memory, that `Tensorize` names an intrinsic the target supports, and that
vector widths are allowed. `Validated` keeps what the checks established
for lowering: the block's thread count and each staged tile's extents.

`CacheRead` stages an input as TVM's `cache_read` with `compute_at` does.
Its loads must share one index without gathers. The tile spans the serial
loops inside `at` and every loop bound to a thread, since the block shares
it; along each input axis it is a box, so validation refuses an index that
does not grow affinely, with non-negative coefficients, over those loops.
`Reindex` makes the tile a box in the iteration space instead, as
MetaSchedule's `ReIndex` does: one coordinate per group of axes, fused
row-major, so a convolution's input stages as the matrix of an implicit
GEMM (D70).

`rfactor` splits a definition's reduction over one axis into equal
slices, as TVM's `rfactor` does, into two definitions (D75). The partial
one reduces each slice, the slice its outermost spatial axis, into
partials of the reduction's own type; the combine one reduces the slices
with the same op inside the original's output expression. Each input the
axis indexes is viewed with that dimension split as `[slices, chunk]`,
which moves no row-major element, so every index stays a plain axis and a
split product is a batched product the tiling rules take unchanged. An
axis read any other way, or by a gather, is refused.

**3. Lowered kernel: an explicit loop nest.** This is a tree of owned
statements, as in TVM's TIR. Index arithmetic and data arithmetic are
different types, so an address can never be computed from loaded data by
accident (gathers go through an explicit `LoadIndex` into an index).

```rust
pub struct LoweredKernel {
    name: KernelName, params: Vec<KernelParam>,                 // global buffers, each Read or Write
    buffers: IndexVec<BufferId, Buffer>,                        // name, dtype, MemScope::{Global, Shared { swizzle }, Local, Fragment}, size
    vars: IndexVec<VarId, KernelVar>,                           // Loop, Thread { axis }, Loaded
    launch: LaunchShape, smem: SmemBytes, body: Stmt, exprs: ExprArena,
}
pub enum Stmt {
    Seq(Vec<Stmt>),
    For { var: VarId, extent: Dim, kind: ForKind, body: Box<Stmt> },     // Serial, Unrolled, Vectorized
    If { condition: Condition, then: Box<Stmt> },                       // index < bound
    Alloc { buffer: BufferId, body: Box<Stmt> },                        // shared or local
    LoadIndex { var: VarId, buffer: BufferId, index: ExprId, body: Box<Stmt> },
    Store { buffer: BufferId, index: ExprId, value: ValueExpr },
    Barrier,
    FragmentFill { fragment: FragmentTile, value: Scalar },              // the whole warp at once
    FragmentLoad { fragment: FragmentTile, source: BufferId, at: TileAccess }, // from shared memory
    Mma { instruction: MmaInstruction, a: FragmentTile, b: FragmentTile, accumulator: FragmentTile },
    FragmentEach { fragment: FragmentTile, row: VarId, column: VarId, body: Box<Stmt> }, // ValueExpr::Element
    AsyncCopy { target: BufferId, target_index: ExprId, source: BufferId, source_index: ExprId,
                run: Dim, bounds: Vec<Condition> },                   // cp.async: global to shared, zero where a bound fails
    AsyncCommit,                                                        // closes the thread's group of copies
    AsyncWait { pending: u32 },                                         // lands all but the newest `pending` groups
}
```

`Schedule<Validated>::lower` turns loops bound to grid and block axes into
those indices and guards into `If`s. A reduction's update that reads only
staged tiles runs under its reduction loops' guards alone: its tiles hold
the overhang, and the store's spatial guards discard what it sums there,
as CUTLASS predicates only a tile's global loads and stores (D76). A
reduction keeps an accumulator per spatial point inside its first
reduction loop, as TVM's `decompose_reduction` does, and an f32 sum of a
product accumulates through a fused multiply-add (D57). A reduction bound
to a thread axis combines the threads' partials in shared memory with a
halving tree, with barriers only where every thread reaches them, as
TVM's cross-thread allreduce does.
Arg-reductions combine (value, position) pairs by a rule that depends only
on both, so any loop order or thread split gives the same position. A
staged input's loop allocates its tile, and each iteration fills it between
two barriers, the block's threads copying elements in rounds, before the
loads read the tile instead of global memory. A thread copies the longest
run of 16, 8 or 4 bytes whose length divides the tile's and its input's
innermost extents and the tile's origin along that axis, so a run lies in
one row of both, aligned, with one `AsyncCopy`: its bounds are its first
element's, and it copies zeros where they fail. The fill commits its
copies and waits for them before the second barrier (D63). A tile no such
run fits copies one element at a time.

A pipelined loop's tiles are filled ahead, as CUTLASS's multistage
mainloop does (D64). Each tile's buffer holds `S` iterations' copies, one
per stage, and a load reads the copy `i mod S`. A barrier and the first
`S - 1` iterations' copies, a commit each, come before the loop. Each
iteration waits until at most `S - 2` groups are in flight, so its own
copies have landed, passes a barrier, starts the copies of iteration
`i + S - 1` into the slot iteration `i - 1` read, commits them, and
computes. Validation requires an input staged at the loop and counts each
tile `S` times against shared memory.

A swizzled tile's bytes are permuted as CUTLASS's `Swizzle<B, M, S>`
permutes them (D66): byte `o` is held at `o ^ (((o >> (M + S)) & (2^B -
1)) << M)`, so each `2^M`-byte unit moves within its `2^(M + B)`-byte block
by the bits `S` above it. The swizzle belongs to the shared buffer's scope,
`MemScope::Shared { swizzle }`, so indices stay affine and every analysis
on them is unchanged; units are at least 16 bytes, so no copy or
`ldmatrix` row straddles two. Validation and the verifier require the tile
to hold whole blocks, so bytes never leave it. `Swizzle::for_tile` picks
CUTLASS's swizzle for a row-major tile: 16-byte units permuted by the row's
place among 8, so the 8 rows an `ldmatrix` reads fall in 8 bank groups.

`Tensorize` makes the innermost three loops of a product one `mma` tile per
warp, the block's `threadIdx.x` its 32 lanes (D58). Validation checks the
loops are innermost inside a reduction step, the definition sums the
product of two loads of the instruction's types, over one axis or, as a
convolution does, several, and both operands are staged outside the tile.
The operand whose tile steps with the tile's rows is the left. Each
holds its tile as rows a fixed distance apart, with adjacent
elements along its rows or its columns, and reading none of the third tile
loop, and every reduction loop inside the tile's first one must come before
the loops over the warp's tiles. Lowering keeps the accumulators in a
fragment array over those tile loops, and each operand's fragments in an
array over the tile loops its tile reads. Each step loads every distinct
fragment once, then multiplies every pair of tiles. The result is stored
through a `FragmentEach` that binds the tile's row and column loops, so the
output's guards and epilogue apply unchanged. Staged tiles hold zeros where
they overhang their input, so an `mma` there multiplies zeros: copies
zero-fill, and an element copy sets the element first, to zero or the
load's padding.
`verify` checks what code generation relies on: variables bound where read,
buffers used as their scope and access allow, shared and local accesses
provably in bounds (with `If` conditions narrowing ranges and capping the
very index they compare), no barrier under
a thread-dependent condition, well-typed values, and asynchronous copies
from a global input to shared memory of 4, 8 or 16 bytes, both runs
starting at a multiple of their length.

Index expressions (`Expr::{Var, Const, Add, Mul, FloorDiv, FloorMod, Min, Max}`)
are hash-consed in an `ExprArena` and addressed by `ExprId`, so structural
equality is id equality and `simplify.rs` can memoise. Division and modulo
round toward negative infinity, as TVM's `floordiv` and `floormod` do. The
simplifier folds sums into a canonical affine form and, given each
variable's range (`VarRanges`, from loop extents), applies TVM's floor
division and modulo rules: `floordiv(c*q + r, c) = q + floordiv(r, c)`,
settled to a constant when `r`'s bounds stay within one multiple of `c`, and
`c*floordiv(x, c) + floormod(x, c) = x`, so split and fuse leave plain
indices.

**Loop-IR interpreter.** `interp/` runs a `LoweredKernel` on the CPU (D41).
Each thread block executes its threads in lockstep, statement by statement,
with the threads an `If` admits active, and every value is rounded or wrapped
to its element type at each operation, as a GPU computes it. Memory starts
unset: reading an element no one stored, or leaving an output element
unwritten, is an error. `race.rs` flags two threads touching one shared
element between barriers (one of them writing) and two threads writing one
global element. An asynchronous copy reads its source when it starts and
lands only at the wait that completes its group, as `cp.async` guarantees
no sooner; touching its elements before, or freeing its tile with it in
flight, is an error, so a missing wait fails on the CPU. A swizzled
buffer holds each element where its swizzle puts the element's bytes, so a
swizzle that does not permute the buffer loses elements. Fragment
statements run once per warp on logical tiles,
`Mma` adding exact products in `k` order and rounding once (D58). A
schedule is therefore checked with no GPU: most scheduling bugs (wrong
tiling, a missing barrier, a bad swizzle, the wrong tile multiplied) are
caught by `cargo test`. The lanes' fragment layouts are codegen's alone,
and the GPU tests check them.

### Lowering (`ptxc-lower`)

- **In:** `Partitioned`. **Out:** `IndexVec<GroupId, LoweredGroup>`: each
  group's stages in order, the intermediate buffers joining them, and the
  constant tables they read, such as per-channel quantization scales (D40,
  D43, D46). A `Stage` is a `ComputeDef` with a `Binding` (a graph value, an
  intermediate or a table) for each of its tensors (D42).
- Arithmetic on f16, bf16 and FP8 values runs in f32 and rounds back once
  (`precision.rs`), as the reference does; comparisons, selects and integer
  arithmetic stay in the operands' own types. Reductions accumulate in f32
  (D43).
- Each op family has one file, mirroring `ptxc-graph/src/ops`. Each produces
  `TensorExpr`s for its stages; an op with several reductions in sequence
  (softmax, layer norm, log-sum-exp) is several stages, built with
  `GroupBuilder` over f32 intermediates (D44). Attention is four such
  stages until M6 fuses it (D48).
- `LoweredGroup::with_split_reductions` replaces a stage whose definition
  scheduling splits with its partial and combine stages, joined by a new
  intermediate for the partials (D75).
- `epilogue.rs` substitutes injective consumers into the producing stage's
  output expression. In M2 every stage is its own kernel; M3's `compute_at`
  places a stage inside another's loop nest, so a group becomes one kernel.

### Scheduling (`ptxc-schedule`)

- **In:** `ComputeDef` and `Target`. **Out:** a `Schedule<Validated>`, from
  a `Trace` replayed from the tuning database, or from `default.rs`.
  In M2, `default_schedule` gives injective stages blocks of 256 threads and
  reductions a block per output row with a shared-memory tree (D49), or a
  thread per output for a reduction no longer than a warp (D73). In
  M3 it tiles a matrix product on CUDA cores, its operands staged in shared
  memory and each thread's outputs in registers (D56). Where the target has
  an `mma` for the product's operand and sum types (f16, bf16, FP8, 8-bit
  integers), it tiles it on tensor cores instead: a block's four warps each
  hold 4 by 8 `mma` tiles of a 128 by 128 block tile, or 2 by 4 of a 64 by
  64 one where fewer than 32 large tiles cover the output or it is
  shorter or narrower than one (D74), both operands
  staged two `mma` steps deep and the innermost tile tensorized (D58). The
  SIMT tile and the 64 by 64 one pipeline their steps over four stages, or
  as many as fit shared memory, the 128 by 128 one over two (D68), and
  both tensor-core tiles swizzle their tiles. A convolution of one group
  is tiled the same way as an implicit GEMM, on tensor cores where the
  target has an `mma` for its types: its operands reindexed as the GEMM's
  matrices, and its output positions, its output channels, and its taps
  with input channels each fused into one loop (D70). A grouped
  convolution's input index reads the output channel, so it keeps the
  reduction rule. A product whose default schedule launches fewer than 32
  blocks is split along its sum first, into slices that launch about 96,
  as many small tiles as the GPU holds at once, each a multiple of 64 and
  at least 128 deep, while the partials move no more bytes than the
  operands hold (D75).
- `ScheduleRule` trait. Each rule decides whether it applies to a compute
  definition and emits *sketches*: traces with symbolic knobs (tile sizes,
  stage counts, vector widths) described by a `SearchSpace`. This is Ansor's
  sketch generation.
- Rules: injective (elementwise), reduction (block or warp), SIMT matmul,
  tensor-core matmul (`ldmatrix` + `mma.sync`, cp.async multi-stage
  pipelines, XOR-swizzled shared memory as in CUTLASS's layouts), and
  implicit-GEMM convolution. Fusing attention online (FlashAttention-2's
  schedule) is the M6 rule.
- `TuningRecord { key: WorkloadKey, target: SmVersion, trace: Trace, latency: Microseconds }`.
  `WorkloadKey` is a hash of the canonical text of the `ComputeDef`.

### PTX code generation (`ptxc-codegen`)

- **In:** `&LoweredKernel` and `&Target`. **Out:** `PtxModule`, printed to
  text.
- The PTX AST is typed. A register carries its PTX type, and each `Instr`
  variant fixes its operand types, so `add.f32` on a `.b16` register cannot
  be built.
- No register allocator is needed: PTX registers are virtual and ptxas (or
  the driver's JIT) allocates them. Codegen still keeps register pressure in
  mind (rematerialising index arithmetic, unrolling deliberately), since
  occupancy depends on it.
- `generate` first expands the loops a schedule marks unrolled, as TVM's
  `UnrollLoop` pass does: one copy of the body per value, indices
  simplified and guards the ranges decide resolved. A thread's tile of
  accumulators then takes constant indices.
- A local or fragment array of elements of at most 4 bytes, every access
  to which is at a constant index once unrolled, is held in registers by
  codegen itself, as LLVM's SROA does for NVVM: one 32-bit register per 4
  bytes, a narrower element shifted and masked out of its word, and merged
  in. Other local arrays are `.local` arrays (D62).
- Instruction selection uses the target's `PtxIsaVersion` and `SmVersion`
  to choose instructions:
  - `cp.async` requires sm_80 or later;
  - `ldmatrix` requires sm_75 or later;
  - FP8 `mma` requires sm_89.
- Values are held by type: floats in f32 registers (narrower ones rounded
  to their type after every operation, D42), 8- and 32-bit integers in
  32-bit registers, wrapped after every operation, `i64` in 64-bit, and
  booleans as predicates. Index arithmetic is `s64`.
- An `AsyncCopy` is one `cp.async`: `.cg` for 16 bytes, as CUTLASS's
  copies are, and `.ca` for 4 and 8, with a `src-size` operand selecting 0
  bytes where a bound fails. A wait forgets every value numbered before it,
  as a barrier does.
- A swizzled shared buffer's byte offset is swizzled before it is added to
  the buffer's address: a constant's at compile time, a computed one's
  with a shift, a mask, a shift and an exclusive-or.
- A vectorized loop that copies or clears a run of 8 or 16 bytes, both
  indices stepping by one and starting aligned to the run, is one
  `ld.v2`/`ld.v4.b32` and `st.v2`/`st.v4.b32`; every buffer starts 256-byte
  aligned. Any other vectorized loop runs serially.
- Index arithmetic is numbered once a block, a loop body's entries
  dropped when it ends. Index expressions that divide and read no variable
  a scope binds are computed once at its start: at the kernel's, those
  reading only grid and block indices, such as a block's place in a grid
  fused onto `blockIdx.x`; at a loop body's, those its own loops, gathers
  and fragment elements do not change, such as a pipelined loop's slot,
  which every guarded load in the body then reuses. A floored
  division or modulo by a power of two is a shift or a mask; by another
  constant, where the dividend's range (from the launch, loops and
  fragment shapes) is known to lie in `0..2^32`, it is 32-bit unsigned
  division, which ptxas multiplies out; otherwise it is `div.s64` with a
  floored fix-up.
- FP8 converts in hardware, which needs PTX ISA 8.1 on `sm_89`; the
  `sm_89` preset declares 8.4 (D50), which FP8 `mma` also needs.
- Fragments follow the PTX ISA's lane layouts, which only codegen knows
  (D58, `select/lanes.rs`). Each lane keeps its elements of a fragment's
  tiles in a local array, held in registers once the loops over a warp's
  tiles are unrolled; `ldmatrix` and `mma` take its words. A multiplicand
  loads with one `ldmatrix` (`.x4` or `.x2`, `.trans` for a 16-bit tile
  stored the other way) where its tile's rows are 16-byte aligned in shared
  memory, and element by element otherwise. Each `Mma` is one `mma.sync`,
  and `FragmentEach` runs its body once per element of the lane (D59).
- Transcendental functions are emitted inline from the math programs the
  loop interpreter evaluates, one instruction per step (D51).
- **Validation:** in tests every emitted module is assembled by ptxas
  (D11). At runtime the driver JIT-compiles the PTX (`cuModuleLoadDataEx`).
  ptxas is never on the compiler path.

### Cost model (`ptxc-cost-model`)

- `CostModel` trait:
  `fn predict(&self, kernels: &[LoweredKernel]) -> Vec<PredictedLatency>`
  and `fn update(&mut self, records: &[MeasuredRecord])`.
- Features follow Ansor: per buffer access, the arithmetic intensity, bytes
  moved per memory scope, the reuse distance, vectorisation, the thread and
  block counts, and the occupancy implied by shared memory and an estimate of
  register use.
- Implementations: `roofline.rs`, an analytical model that needs no data, and
  `learned/`, trained on measured records. Whether that is gradient-boosted
  trees (as in Ansor) or a small MLP (as in TLP) is decided at M5. Neither
  needs a GPU, so models are trained and evaluated in plain tests.

### Program (`ptxc-program`)

This is the boundary between compiler and runtime. It has no IR types in it.

```rust
pub struct Program {
    format: FormatVersion,
    target: SmVersion,
    kernels: IndexVec<KernelId, KernelSpec>,         // PTX text, entry name, LaunchConfig { grid, block, dynamic_smem }
    constants: ConstantBlob,                         // weights, uploaded once at load
    plan: BufferPlan,                                // arena size; ByteOffset per intermediate buffer; aliases
    steps: Vec<Step>,                                // Step::{Launch { kernel, args }, Copy { .. }, Memset { .. }}
    inputs: Vec<IoBinding>, outputs: Vec<IoBinding>,
}
```

A `Program` is saved to disk and loaded again (`format.rs`). The format is
versioned and checked once on load. That makes compile time comparable with
TensorRT's engine build, and lets a tuned model be reused.

### Memory planning (`ptxc-compiler::memory_plan`)

Memory planning is part of compilation, as in XLA's BufferAssignment.

- Buffers are the outputs of fused groups that are neither graph inputs nor
  graph outputs.
- `lifetime.rs` computes each buffer's live range over the step order.
- A `MemoryPlanner` assigns byte offsets in a single arena so that buffers
  whose live ranges overlap never overlap in memory. Two planners are
  planned: greedy-by-size (TensorFlow Lite's planner) and linear scan.
- The output is checked by an independent verifier in tests: no two live
  buffers overlap, and every buffer is aligned.

### CUDA bindings (`ptxc-cuda`)

- `sys/` resolves about 40 driver API functions from `libcuda.so.1` with
  dlopen into a function-pointer table. Without a driver, the crate still
  builds and `Driver::load()` returns an error.
- The safe layer is small and owns every handle with RAII:

```rust
let driver = Driver::load()?;
let device = driver.device(DeviceOrdinal::new(0))?;
let ctx = device.primary_context()?;
let module = ctx.load_ptx(&ptx)?;
let kernel = module.function(&KernelName::new("matmul_0"))?;
let stream = ctx.stream()?;
let mut buf = ctx.alloc(ByteSize::new(bytes))?;   // device memory is bytes
buf.copy_from_host(&host_bytes)?;

kernel.launch()
    .grid(GridDim::new(64, 1, 1))
    .block(BlockDim::new(128, 1, 1))     // .launch() is only callable once grid and block are set
    .dynamic_smem(ByteSize::new(49_152))
    .arg(&buf)                           // checked against the kernel's parameter sizes
    .launch(&stream)?;
```

- Every handle holds an `Arc` of its context, and each call makes that
  context current on the calling thread (D37).
- `CudaError` carries the driver's error name, the call that failed and,
  for a failed PTX load, the JIT's log.
- No host memory is mapped into the device's address space, which is what
  makes a safe launch sound (D37). Stream capture and CUDA graphs come with
  the graphed executor (M4).
- `unsafe_code` is denied workspace-wide and allowed only in `ptxc-cuda`
  and in `ptxc-bench`'s cuBLAS bindings (D55); `cargo xtask check-deps`
  enforces both.

### Runtime (`ptxc-runtime`)

- `load.rs` takes a `Program`, loads its modules, allocates the arena and
  uploads its constants, producing a `LoadedProgram`.
- `Executor<Eager>` runs the steps in order on one stream. `bind` keeps a
  program's inputs and outputs on the device, so a caller can queue it
  repeatedly on its own stream with no host copies, as the benchmarks do.
  `.capture(self) -> Result<Executor<Graphed>, RuntimeError>` records them
  into a CUDA graph once. Replays then copy the inputs into fixed staging
  buffers and launch the graph.
- `Target::from_device` is built here from device attributes (SM count,
  shared memory per block when opted in, L2 size) on top of the preset for
  the device's SM version.
- Implements `Evaluate`.

### Autotuner (`ptxc-autotune`)

- Tasks are the distinct `WorkloadKey`s of a model's compute definitions,
  weighted by how often each occurs.
- For each task, the sketches come from the schedule rules. The search
  (`SearchStrategy`: random, or evolutionary as in Ansor) proposes knob
  values. The cost model ranks them, and the `Measurer` times the top *k*.
  Measured records update the cost model.
- `Tuner` divides trials between tasks by expected end-to-end gain, as
  Ansor's task scheduler does.
- The `Measurer` implementations:
  - `gpu.rs` compiles, launches and times each candidate with events, and
    checks every candidate's output against the loop interpreter on small
    inputs before it is timed;
  - `model_only.rs` makes the whole tuner testable without a GPU.
- Records are appended to a JSON-lines database, which `ptxc-compiler` reads
  as data.

## How information flows

| Producer | Artifact | Consumer | Carries |
|---|---|---|---|
| onnx | `Graph` | graph-opt | typed ops, static `TensorType` on every value, constants |
| graph-opt | `Partitioned` | lower, memory plan | fused groups, group DAG, view aliases |
| lower | `ComputeDef` per group | schedule, autotune | iteration domain, expressions, `WorkloadKey` |
| schedule / autotune | `Trace` | loop | the replayable schedule |
| loop | `LoweredKernel` | codegen, cost-model, loop interp | explicit loops, scopes, launch shape |
| codegen | `PtxModule` text | program | kernel source |
| compiler | `Program` | runtime | kernels, plan, steps, constants, I/O |
| runtime | `GpuMeasurement` | autotune | measured latency per candidate |

## Extension points

Each trait below exists because the roadmap commits to at least two
implementations.

| Trait | Crate | Implementations |
|---|---|---|
| `Evaluate` | core | `Interpreter`, loop-IR interpreter, GPU `Executor`, cached ORT/PyTorch outputs |
| `TypeRule` | graph | every op attribute struct |
| `Pass` | graph-opt | each pass |
| `RewriteEngine` | graph-opt | `GreedyEngine`, later `EGraphEngine` |
| `Partitioner` | graph-opt | greedy, attention-aware |
| `ScheduleRule` | schedule | one per kernel family |
| `CostModel` | cost-model | roofline, learned |
| `MemoryPlanner` | compiler | greedy-by-size, linear scan |
| `SearchStrategy` | autotune | random, evolutionary |
| `Measurer` | autotune | GPU, model-only |
| `Calibrator` (M7) | graph-opt | min-max, percentile, entropy |

New architectures add a preset and mma table rows in `ptxc-target`, and new
selection cases in `ptxc-codegen` where the ISA differs. Nothing else names an
architecture.
